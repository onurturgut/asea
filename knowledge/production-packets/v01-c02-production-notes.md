## Content

### Learning Sequence

1. Activate the Chapter 01 distinction between representation and execution.
2. Establish source code versus running program.
3. Compare bounded compiler, interpreter, and runtime paths.
4. Introduce explicit program state.
5. Trace ordered instructions and one control transfer.
6. Add execution memory as selected state.
7. Combine the model into a deliberately simplified CPU abstraction.
8. Apply the model through prediction, trace, debugging, Lab, and assessment.
9. State where the abstraction stops being valid.

### Evidence Discipline

Every material technical statement must map to a packet claim ID. Organization-specific or performance claims are prohibited until a Tier 3 source is registered and validated.

### Required Model Warning

The final chapter must state that the tiny machine is an architectural and pedagogical abstraction. It is not a physical CPU diagram, a universal language pipeline, or a cycle-accurate execution model.
