# Quiz Cevap Anahtarı

## Kullanım Uyarısı

Bu dosyayı yalnız [quiz](./quiz.md) cevaplarını kilitledikten sonra aç.

## Yanıtlar ve Açıklamalar

1. **B:** Prompt anlamı type garantisi değildir; readline satırı String verir.
2. **B:** Veri farklı güven/sözleşme koşulları arasından geçer.
3. **B:** Parsing representation'ı program değerine yorumlar.
4. **A:** Validation değerin tanımlı constraints'e uyumunu ölçer.
5. **B:** `Number("")` 0 üretir; required check önce yapılmalıdır.
6. **B:** `parseInt` geçerli prefix 12'yi kabul eder.
7. **B:** Entire-input contract bozulup trailing text sessizce yok sayılır.
8. **B:** Yalnız JSON syntax/parse başarısı kanıtlanır.
9. **B:** Parse başarılı, semantic range validation başarısızdır.
10. **B:** Metin biçimi syntactic kuraldır.
11. **B:** Domain aralığı semantic kuraldır.
12. **B:** Eşdeğer girdiler tanımlı canonical forma gelir.
13. **B:** Field semantics farklıdır; normalization data loss yaratabilir.
14. **B:** Formatting output boundary'de tüketiciye göre yapılır.
15. **B:** Locale-specific display String hesap değeri değildir.
16. **B:** Client hızlı UX feedback sağlar; authoritative validation yine gerekir.
17. **B:** Uygun bütün hataları bir response'ta toplar.
18. **B:** Alan, code ve correction kullanıcı/machine ihtiyaçlarını ayırır.
19. **B:** Transformation validated values'dan domain record üretir.
20. **B:** Hat trust'ın kademeli güçlenmesini gösterir.
21. **B:** Sonlu olmayan numeric sonuçlar reddedilebilir.
22. **B:** İki alan arasındaki ilişki record-level rule'dur.
23. **C:** Raw secret loglanmamalıdır.
24. **B:** AI output external input gibi doğrulanır.
25. **B:** Öğrenme çıktısı açıklanabilir, test edilmiş pipeline ister.

## Sonuç Yorumlama

- **23–25:** Laboratuvara geç.
- **20–22:** Yanlış aşamaları tekrar ederek laboratuvara geç.
- **16–19:** Ana dersin parsing/validation ve normalization bölümlerini yeniden uygula.
- **0–15:** Contract ve pipeline mental modelini baştan çalış.
